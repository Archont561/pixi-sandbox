## Overview

Your workflow just uses the two actions in the same repo — like `prefix-dev/setup-pixi`. No `release-repository` / `release-version` needed, your `uses: @v0.2.0` pin *is* the version.

1. `plan --json` validates `.pixi-sandbox.toml` and emits a native `runner` per `bundle × platform`
2. For each matrix entry, on that native runner: `setup` (verified download) → `publish` (install → pack `--fetch-tools --self-bin` → `doctor --verify` → orphan branch push)

## Quick start in your repo — just two actions

### 1. Add `.pixi-sandbox.toml`

```toml
schema = 1
branch_prefix = "sandbox"
cargo_vendor = true

[runners]
# Override if you need self-hosted or special labels
# osx-arm64 = "macos-14"
# linux-aarch64 = "self-hosted-arm64"  # required — no hosted default

[[bundle]]
name = "developer"
environments = ["dev", "docs"]
platforms = ["linux-64", "osx-arm64", "win-64"]
```

### 2. Create workflow (recommended)

Multi-platform matrix — validates config then publishes one native branch per job:

```yaml
# .github/workflows/publish-sandbox.yml — your project
name: publish sandbox
on:
  push: { branches: [main] }
  workflow_dispatch:

jobs:
  plan:
    runs-on: ubuntu-latest
    outputs: { matrix: ${{ steps.plan.outputs.matrix }} }
    steps:
      - uses: actions/checkout@v7.0.1
      - uses: Archont561/pixi-sandbox/setup@v0.2.0
        id: setup
        with: { version: v0.2.0 }
      - id: plan
        run: echo "matrix=$(${{ steps.setup.outputs.path }} plan --config .pixi-sandbox.toml --json)" >> $GITHUB_OUTPUT

  publish:
    needs: plan
    strategy: { matrix: ${{ fromJSON(needs.plan.outputs.matrix) }}, fail-fast: false }
    runs-on: ${{ matrix.runner }}
    steps:
      - uses: actions/checkout@v7.0.1
      - uses: prefix-dev/setup-pixi@v0.10.2
      - uses: Archont561/pixi-sandbox/setup@v0.2.0
        id: setup
        with: { version: v0.2.0 }
      - uses: Archont561/pixi-sandbox/publish@v0.2.0
        with:
          project: .
          environments: ${{ matrix.environments }}
          platform: ${{ matrix.platform }}
          branch: ${{ matrix.branch }}
          self-bin: ${{ steps.setup.outputs.path }}
          remote: https://github.com/${{ github.repository }}.git
          output-dir: /tmp/transport
          push-token: ${{ secrets.GITHUB_TOKEN }}
```

Pin to SHA for supply-chain security:

```yaml
- uses: Archont561/pixi-sandbox/setup@<immutable-sha>
  with: { version: v0.2.0 }
- uses: Archont561/pixi-sandbox/publish@<immutable-sha>
```

Single platform without `plan`:

```yaml
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7.0.1
      - uses: prefix-dev/setup-pixi@v0.10.2
      - uses: Archont561/pixi-sandbox/setup@v0.2.0
        id: setup
        with: { version: v0.2.0 }
      - uses: Archont561/pixi-sandbox/publish@v0.2.0
        with:
          project: .
          environments: dev,docs
          platform: linux-64
          branch: sandbox/developer-linux-64
          self-bin: ${{ steps.setup.outputs.path }}
          remote: https://github.com/${{ github.repository }}.git
          output-dir: /tmp/transport
          push-token: ${{ secrets.GITHUB_TOKEN }}
```

### 3. What happens

- `plan --json` emits matrix like `sandbox/developer-linux-64`, `sandbox/developer-osx-arm64`, etc.
- Each native `publish` job:
  ```text
  pixi install --frozen -e <envs>
  → pixi-sandbox pack --fetch-tools --self-bin <verified release from setup>
  → pixi-sandbox doctor --verify
  → pixi-sandbox publish --branch-name <branch> --remote <url>
  ```
- Branch contains verified Rust binary as self-bootstrap.

## Alternative: reusable workflow

If you prefer one line instead of `plan` + matrix:

```yaml
jobs:
  publish:
    uses: Archont561/pixi-sandbox/.github/workflows/publish-sandbox.yml@v0.2.0
    with:
      config: .pixi-sandbox.toml
      release-repository: Archont561/pixi-sandbox
      release-version: v0.2.0
    secrets:
      SANDBOX_PUSH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

That workflow internally does the same `setup` + `publish` steps but needs the duplicate `release-*` inputs because `uses: @v0.2.0` is not auto-forwarded as a binary version. Prefer the two-action workflow above to avoid duplication.

## Custom runners

For platforms without hosted default (currently `linux-aarch64`), you must provide `[runners]`:

```toml
[runners]
linux-aarch64 = "self-hosted-arm64"

[[bundle]]
name = "dev"
environments = ["dev"]
platforms = ["linux-64", "linux-aarch64"]
```

`plan` also requires embedded pins for `pixi`, `pixi-pack`, `pixi-unpack` — prevents custom runner from reaching job that can't download verified tools.

## One-liner rule

Source-driven workflow steps are one line: `pixi run -e <env> <task>`. Logic lives in `pixi.toml` tasks, not YAML — so CI command = local command.

```yaml
- run: pixi run -e ci ci-pack
- run: pixi run -e ci ci-doctor
- run: pixi run -e ci ci-publish
```

Paths come from `SANDBOX_*` env vars set in workflow `env:` block.

## Dependabot

Add `.github/dependabot.yml` to keep actions and cargo deps fresh (convco-compatible prefixes):

```yaml
version: 2
updates:
  - package-ecosystem: github-actions
    directory: "/"
    schedule: { interval: weekly }
    commit-message: { prefix: ci }
  - package-ecosystem: cargo
    directory: "/"
    schedule: { interval: weekly }
    commit-message: { prefix: chore, include: scope }
```
