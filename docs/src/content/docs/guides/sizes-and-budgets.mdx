A transport is pushed to a Git host, so its size is not a preference — it is a set of enforced
limits. This page covers the measured numbers, the sharding mechanism, and the budgets `doctor`
checks before any branch is force-pushed.

## Historical measurement: a helper-based small project

This pre-native snapshot used 2 environments, 33 crates and `linux-64`, with helpers included.
It is historical evidence, not a current native size baseline:

| Part | Size |
|------|------|
| conda envs (`.conda` channel) | 133 MB |
| cargo vendor tree (loose) | 33 MB |
| bundled tools (pixi, pixi-unpack, self) | 96 MB |
| **transport dir** | **262 MB** |
| **orphan branch after git dedup** | **~110 MB** |

New schema-4 transports omit pack/unpack helpers; only explicitly selected Pixi/bootstrap
executables count toward tool bytes. Measure the current manifest with `doctor` rather than
subtracting guessed helper savings from this table. In the historical measurement, tools
dominated small bundles — expected, because Git stores each tool blob once and the tools are
identical across bundles. A second bundle that reuses the same tool versions adds only its own
environment bytes.

## Sharding: why no single file is oversized

GitHub rejects a blob larger than 100 MiB, and other hosts impose their own limits. `pack`
therefore shards whole files above the shard limit — default **95 MiB** — into `.partNNN` parts,
and `restore` re-joins them atomically (`join_parts`) after verification:

<ContextChips chips={["connected"]} />

```bash
pixi-sandbox pack ... --shard-limit-mib 95
```

Sharding is whole-file and content-addressed: Git deduplicates unchanged shards across publishes,
so a one-crate bump republishes only the changed bytes (measured: +0.07 MiB). Nothing is split
inside a single environment — a growing transport is split by *bundle*, never by cutting an
environment in half.

## Budgets: checked before the push

`[budgets]` in `pixi-sandbox.toml` sets hard ceilings. The generated publisher runs
`doctor --verify --budget-config <config>` after `pack` and **before** `publish`, so an over-budget
transport fails without replacing the last healthy orphan branch:

| Field | Default | Measures |
|-------|---------|----------|
| `max_blob_mib` | `95` | Largest stored Git object: an unsplit blob, split part, embedded tool, or per-file oracle blob |
| `max_transport_mib` | `2048` | Declared bytes verified by `doctor`: env pack blobs, per-file-oracle blobs, tools, vendored crates |
| `max_repository_push_mib` | `2048` | File bytes staged into the orphan snapshot before Git compression |
| `max_restore_required_mib` | `8192` | Restore preflight estimate: packed + unpacked env bytes plus two vendor copies |

```toml
[budgets]
max_blob_mib = 95
max_transport_mib = 2048
max_repository_push_mib = 2048
max_restore_required_mib = 8192
```

Budgets never change the transport format. When a bundle grows past a ceiling, the remedy is always
the same shape: **publish fewer environments per `[[bundle]]`**. Do not split one environment, and
do not move payload outside the self-contained branch — a branch that is not self-contained cannot
be restored offline.

## Rotation is not a shrink

`publish --keep N` keeps the N most recent snapshots on a branch. Dropping a snapshot makes its
objects *unreferenced, not deleted*: a force-push followed by `git gc --aggressive` on the server
has been measured **not** to reclaim the space, and a hosted server may keep unreferenced objects
for a long time. `--keep N` bounds what the branch *serves* — which bounds what an airlock fetches —
but reclaiming disk on the remote still needs an administrator to prune, or the branch to be
recreated under a new name.

## When a ceiling is exceeded

`doctor --budget-config` fails read-only and names the exceeded ceiling and its remedy. The safe
response is to split the reviewed environment set into separate `[[bundle]]` entries and republish;
the failed run never touches the existing branch. Symptom-level guidance is in
[Troubleshooting and incident response](/pixi-sandbox/troubleshooting/).

## Verification

`doctor --verify --budget-config <config>` is green against the ceilings above, and
`publish --dry-run` previews the push without touching the remote:

<ContextChips chips={["connected"]} />

```bash
pixi-sandbox doctor --branch-location .sandbox-out --verify --budget-config pixi-sandbox.toml
pixi-sandbox publish --input-dir .sandbox-out --branch-name sandbox/dev-linux-64 --dry-run
```

## Failure modes

- **A ceiling is exceeded** — `doctor --budget-config` fails read-only and names the ceiling and its
  remedy; the failed run never touches the existing branch. Entry 7 in
  [Troubleshooting and incident response](/pixi-sandbox/troubleshooting/) covers the CI shape.
- **The host rejects a push for an oversized object** — entry 5 (a single blob over the host's
  limit): lower `max_blob_mib` or shard, and republish.
