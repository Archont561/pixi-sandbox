## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Follow-up to umbrella TASK-122 (Reduce GitHub Actions minutes RFC #179) and children TASK-118 (double bootstrap), TASK-119 (plan job VM overhead), TASK-120 (default concurrency), TASK-121 (relock path filtering). Most marked Done but with remaining ACs.

Current CI (`ci.yml`):
- 2 jobs: `ci (lint · test · coverage)` on ubuntu-latest (fmt --check, lint, test, test-payload-roundtrip, coverage, docs build, check-main-push guard ADR-29) + `replace a running image (windows)` on windows-latest (test-self-update-replace, TASK-47 AC#2)
- Concurrency: `group: ci-${{ pr_ref || sha }}, cancel-in-progress: true` for PRs, main pushes never cancelled (ADR-29)
- Caching: setup-pixi cache, rust-cache, turbo cache

`relock.yml` (generated by `init`, now with paths filter from TASK-121):
- on.pull_request.paths: manifests + lockfiles (Cargo.toml, **/Cargo.toml, Cargo.lock, pixi.toml, pixi.lock, package.json, bun.lock, .pixi-sandbox.toml) – saves 1 min per docs-only PR
- guard: `pixi lock --check` + `cargo fetch --locked` (10s wall, 1 billed min)
- relock job only when guard failure + PR, with fork refusal

`publish-sandbox.yml` (this repo source-built variant, consumer template is release-based):
- plan job: builds planner binary from source (56s) + `plan --json` <1s – 2 billed mins, 1 min billed for consumers (setup-pixi 1s + conda install pixi-sandbox 2s)
- publish job matrix: setup-pixi 1s + conda install pixi-sandbox 10s (32% overhead) + fetch-release <1s + pack 15s + upload artifact 1s = 31s wall, 1-2 billed mins
- Has concurrency `group: publish-sandbox-${{ repository }}, cancel-in-progress: false` (this repo) but generated consumer template had none before TASK-120

Issue #179 reports 40-60% billing overhead.

**Remaining optimizations (TASK-118 AC#4,5 still open):**
- Replace conda install + `fetch-release` double bootstrap with curl + sha256sum verification in shell (preserves checksum verification, static musl guarantee ADR-4, TASK-76). Saves 10s per publish job (40s for 4 platforms).
- Make plan job cheaper: use standalone binary via curl instead of conda install (saves 2s consumer) or make matrix static at generation time when `[workflow] static_matrix = true` (saves 1 min per push, 100 pushes = 100 min)
- Add `paths:` filter to `ci.yml` itself to skip docs-only changes (keep check-main-push always on push)
- Gate `upload-artifact docs-site` on push only, not PRs
- Ensure `run-install: false, cache: false` for plan job (already done for this repo)

**Work:**
- Implement curl-based bootstrap in `crates/pixi-sandbox/src/generated/github_workflow.rs` – replace "Install pixi-sandbox CLI" step with direct curl + grep SHA256SUMS + sha256sum -c + chmod +x
- Update golden file `crates/pixi-sandbox/tests/fixtures/github_workflow/...` and `the_render_embeds_no_release_asset_names` test (currently asserts no asset names embedded – curl approach re-embeds them, needs ADR update)
- Add default concurrency to generated consumer workflow (TASK-120) – `group: publish-sandbox-${{ github.ref }}, cancel-in-progress: true` or repository-wide
- Add paths filter to ci.yml template via `[workflow]` config similar to relock_paths derivation
- Measure minutes saved: before/after for docs-only PR, manifest PR, 2 consecutive merges

Reference: https://github.com/Archont561/pixi-sandbox/issues/179, TASK-118/119/120/121/122, ADR-18/29

### 2026-10-22 — Local implementation; live proof and dependency gate outstanding

- Replaced conda CLI installation plus `fetch-release` with one curl + SHA256SUMS bootstrap
  in generated plan, publish and upgrade jobs. Asset names are emitted from `Platform`, with
  OS **and architecture** matching and musl for Linux. HTTPS-only downloads stage into a fresh
  temporary directory. Exact filename selection, one valid digest and checksum verification
  precede installation/PATH registration; duplicate/missing/malformed entries fail closed.
  Supports GNU sha256sum and macOS shasum, CRLF manifests and binary-mode checksum entries.
- Dynamic plan now uses the verified standalone CLI and no setup-pixi/conda install. Static
  matrix mode was deliberately not implemented: the latest config remains authoritative.
  This repository's source-built publisher is intentionally unchanged for dogfooding.
- ADR-30 documents the narrowly scoped multiline bootstrap exception to TASK-76, security
  boundary, dynamic-matrix choice and billing caveat. Golden, CLI compatibility ratchets,
  consumer-proof assertions, repository checks and publishing/migration guides were updated.
- Default repository-wide concurrency with `cancel-in-progress: false` already existed
  (TASK-120). Verified it in the golden/default render and retained explicit overrides. AC#3
  is checked for the implemented serialization/coalescing policy; no live numeric saving is claimed.
- `ci.yml` filters expensive Rust/cache/coverage steps with a SHA-pinned paths-filter action,
  **not** workflow-level paths (which can strand required checks Pending). Docs/backlog-only
  PRs still lint docs and build the site, and skip the Windows Rust job. Mixed/code PRs run
  everything; missing filter output defaults to full checks, and filter errors fail CI.
  All pushes keep full CI and ADR-29's `!cancelled()` main guard. Repository variable
  `PIXI_SANDBOX_FULL_CI=true` disables filtering. This is repository CI policy, not a new
  `[workflow]` setting for a CI generator that does not exist. Docs-site upload is push-only.
- Relock filtering is unchanged and its committed render equals the generator. Its allowlist
  includes manifests and lockfiles, so edits/deletions of locks still schedule the guard.
  The selected paths-filter implementation treats renames as delete+add, preserving both paths.
