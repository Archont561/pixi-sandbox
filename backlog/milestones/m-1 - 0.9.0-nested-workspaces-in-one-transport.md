## Description and exit criteria

A repository with explicitly declared nested Pixi workspaces packs to **one** transport and
restores on an airlock as a single, verifiable tree: every declared workspace's environments,
its Cargo vendor tree and its tools come from the same manifest, and the airlock gate proves
the restored workspace set — not only the root one.

Exit criteria:

1. TASK-129 is closed: the nested transport is packed, restored and verified on a transport
   whose lockfile pixi itself generated (its one remaining obstacle, AC#7).
2. TASK-131 is closed: per-workspace Cargo vendor trees travel in the same transport and the
   restored tree wires each workspace to its own tree.
3. The airlock gate — `airlock linux-64`, both tiers — is green on the release branch, with the
   nested workspace present in the proof transport, not only in a fixture.
4. The release gate task's acceptance criteria are checked and `v0.9.0` is published by
   `release.yml` (five static binaries, conda packages, `SHA256SUMS`).

## Sprint train

One sprint. The board has no open milestone-carrying tasks today; the sprint below is the

  `release` + `publish sandbox` runs.

Out of this milestone: TASK-130 (Go, NuGet and Maven vendoring — m-2, after its own spike) and
TASK-73 (deprecated).

## Version policy

0.9.0 is a SemVer planning target and is not published until the release gate cuts it. This
project is pre-1.0: a breaking transport or manifest change is a **minor** bump (0.8.0 → 0.9.0),
fixes are patches, and prereleases may use a suffix (`0.9.0-rc.1`) — a suffix makes `release.yml`
dry-run the registries instead of publishing. Package versions and transport schema versions are
independent; do not bump manifests while planning. 1.0.0 needs its own explicit stability
decision and is not a planning default.

## Release gate

The milestone is closed by its release-gate task, never by a merge: the task's acceptance
criteria are the tag, the published assets, the green airlock and the closed milestone file.
Until that task exists on the board (doc-18 §5.3), this milestone cannot close — a milestone
whose release nobody owns is a date, not a commitment.
